# TaskForge – Smart Todo Management REST API

## About the Project

TaskForge is a REST API I built using Java and Spring Boot to manage tasks. It allows users to create, view, update, and delete tasks. Task data is stored in PostgreSQL.

I also added pagination, filtering, sorting, input validation, and Swagger documentation to make the API easier to use and test.

## Features

- Create, view, update, and delete tasks (CRUD)
- Manage task status and priority
- Pagination and filtering by status
- Sort tasks by supported fields
- Validate request data and handle errors
- Interactive API documentation using Swagger UI
- Store task data in PostgreSQL

New tasks default to `TODO` status and `MEDIUM` priority when these fields are omitted.

## Getting Started

### 1. Create the Database

Open PostgreSQL and run:

```sql
CREATE DATABASE taskforge;
```

### 2. Configure Database Connection

Set your PostgreSQL connection details in PowerShell. Replace the placeholders with your own credentials.

```powershell
$env:SPRING_DATASOURCE_URL = "jdbc:postgresql://localhost:5432/taskforge"
$env:SPRING_DATASOURCE_USERNAME = "<your-username>"
$env:SPRING_DATASOURCE_PASSWORD = "<your-password>"
```

### 3. Run the Application

Open a terminal in the project directory and execute:

```powershell
.\mvnw.cmd spring-boot:run
```

The application runs on port `8080` by default.

## API Endpoints

All endpoints use the base path `/api/tasks`.

| Method | Endpoint | Description | Success Status |
|---|---|---|---|
| POST | `/api/tasks` | Create a task | 201 Created |
| GET | `/api/tasks` | Get a paginated task list | 200 OK |
| GET | `/api/tasks/{id}` | Get a task by ID | 200 OK |
| PUT | `/api/tasks/{id}` | Update a task | 200 OK |
| DELETE | `/api/tasks/{id}` | Delete a task | 204 No Content |

Invalid request data returns `400 Bad Request`. If a task does not exist, the API returns `404 Not Found`.

## Pagination, Filtering and Sorting

The `GET /api/tasks` endpoint supports the following query parameters.

| Parameter | Default | Description |
|---|---|---|
| `page` | `0` | Page number, starting from zero |
| `size` | `10` | Number of tasks per page; allowed range: 1–100 |
| `status` | None | Filter by `TODO`, `IN_PROGRESS`, or `DONE` |
| `sort` | `createdAt` | Sort by `createdAt`, `dueDate`, `title`, or `priority` |
| `direction` | `DESC` | Sort order: `ASC` or `DESC` |

Example request:

```http
GET /api/tasks?page=0&size=5&status=TODO&sort=dueDate&direction=ASC
```

## Example Request

Send this JSON body to `POST /api/tasks` to create a task.

```json
{
  "title": "Prepare project demo",
  "description": "Review the API and prepare a short walkthrough",
  "status": "IN_PROGRESS",
  "priority": "HIGH",
  "dueDate": "2026-11-05"
}
```

The `title` field is required. The description and due date are optional. The status and priority use the supported enum values.

## Example Task Response

A successful request returns a task similar to this:

```json
{
  "id": 1,
  "title": "Prepare project demo",
  "description": "Review the API and prepare a short walkthrough",
  "status": "IN_PROGRESS",
  "priority": "HIGH",
  "dueDate": "2026-11-05",
  "createdAt": "2026-10-25T10:15:30",
  "updatedAt": "2026-10-25T10:15:30"
}
```

The ID and timestamps are generated by the application.

## Swagger Documentation

Once the application is running, open:

- **Swagger UI:** http://localhost:8080/swagger-ui.html
- **OpenAPI JSON:** http://localhost:8080/v3/api-docs

Swagger UI lets you explore the available endpoints and send requests directly from your browser.

## Run Tests

To run the automated test suite, execute:

```powershell
.\mvnw.cmd test
```

The current test suite passes 30 tests. The tests use mocked dependencies, so they do not verify database persistence against a live PostgreSQL instance.
